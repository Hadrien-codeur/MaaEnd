# 固定滑索路线接入流程模板

> 用于后续新增固定取货/送货路线。路线必须先有当前设施和实机证据，再进入业务接线。

## 1. 范围与数据

每条路线先确定地图/Level、仓储与终点 ID、固定路线 ID、滑索形态、支持入口和验收目标。未确认路线只保留调研记录和独立测试入口。

必须准备当前账号 `Ziplines.json`、每座滑索架的 `template_id`/`level_id`/世界 `x/y/z`、供电和连接证据、设施快照时间与账号标识。

分别录制传送落点到首架、末架到仓储/交付站位、仓储到送货首架、交付末架到交互点的地面路线，并标注桥面、设备边缘、缺失网格和绕行点。公共路径与固定路线专用路径分开维护。

每个交互点记录站位 P、朝向对象 T、上索/下索/取货/交货提示、是否需要 `HEADING`、转向后是否重新识别和失败出口。

## 2. 配置顺序

1. 在 `fixed_zipline_routes.json` 新增完整有向架序，先不接业务。
2. 用当前快照校验唯一匹配、层级、顺序、供电和配置异常。
3. 在 AutoDelivery 路线源新增独立固定 ID，保留普通 `path`、`retry_path`、`departure_path` 语义。
4. 生成 Pipeline，确认 WithZipline 节点携带固定 ID，普通节点和站位修正节点不携带。
5. 新增独立测试入口，复用正式组件，不复制业务流程。
6. 无订单实测通过后，再接入抢单和装箱自送分发。

## 3. 测试顺序

### 静态与自动化

检查 JSON、Schema、资源、固定路线唯一匹配、缺架/错层/歧义/反向/坏配置、地面路径完整性、普通路线兼容、全局禁滑和 `walk_only` 行为，并运行生成器和节点测试。

### 独立无订单

依次测试：只跑取货到仓储即停；只跑送货到交付站位即停；取货到送货连续空跑并跳过交互；记录上索、落架、设备阻挡、末端站位和朝向。

### 真实业务

覆盖新接委托、已取货恢复、抢单、装箱自送、取消重启、路线失败、识别失败、全局禁滑，以及成功/失败出口。失败不能继续装箱或报告完成。

## 4. 收尾记录

记录配置提交、设施快照、测试入口、控制器、自动化结果、无订单结果、真实订单来源/目的地/货物状态/最终出口、已知限制和未覆盖场景。原始日志、账号配置、截图原图和构建产物留在本机。

武陵城取货 → 苏白易送货可作为当前参考实例；后续路线按本模板重新核验，不直接复制坐标或假设朝向。
