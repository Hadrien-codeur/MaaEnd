## 3. 代码和识别

- Pipeline 负责界面、取货、送货、交付流程；Go 只做终点 ID 和路线选择等必要计算；C++ 在现有导航组件内处理固定架序和接力状态，不接收买家名称或订单业务语义。
- 先复用公共场景接口与已有节点，不直接依赖 `__ScenePrivate*`。新增节点使用 PascalCase 和模块前缀。
- 遵循识别、操作、再识别；把弹窗、加载和中间态纳入流程，不靠盲点、硬延迟、重复重试或随意添加次数限制掩盖错误。
- 新界面节点必须有真实模板、ROI 和跳转证据；缺少材料明确标为待补，不能把猜测坐标放进可执行路线。
- 屏幕截图、模板、点击和 ROI 基于 1280x720；世界三维坐标、地图 base 坐标单独标明坐标系，不能套用屏幕范围。
- 截图前检查 HDR、滤镜及颜色管理；测试截图按 `maaend-test-image` 技能处理 UID。
- OCR 默认写完整文本。确有识别证据需要截断时保留完整原文注释和 `@i18n-skip`。
- 只增加实现已确认需求所必需的参数。注册名、调用点和 Custom Schema 同步更新；删除参数同步清理引用，不创建无意义的空 Schema。
- 修改生成配置时改生成源，重新生成后审查差异，不手改生成结果冒充永久修复。新增选项维护五语言文案。
- 资源目录名不以下划线开头。遵守上游格式配置，避免无关格式化、依赖升级和大范围重构。

## 4. 固定滑索专项约束

- 从当前账号导入设施，以地图、层级、类型、坐标及容差唯一匹配；不以数组序号充当稳定架 ID。
- 每段保存完整有向架序。N 跳等于 N+1 架、N-1 次途中接力；次数从架序派生，不单独手填。
- 指定顺序不得被成本规划换路、重排或跳架；全局 Never 禁滑仍须生效。
- 按 E 发出、画面静止、计数正确均不能单独证明成功。接力提示需去重，末架需有效定位与状态确认。
- 分叉、不确定接力方向及未实测路段先用到架重发射。途中失败不可默默从起点重跑或换路后宣称固定路线成功。
- 记录预期架序、实际执行、失败阶段和是否降级。取消后清除运行状态。

## 5. 环境与验证

进入新版目录后，在 PowerShell 执行 `. .\tools\fixed-delivery\Enter-Dev.ps1`，将 uv、Go、临时下载等缓存限定到当前仓库。脚本只设置当前终端环境，不修改系统全局环境变量。

依赖以 `pnpm-lock.yaml`、`uv.lock`、Go 模块及主仓库记录的子模块提交为准。使用 `pnpm install --frozen-lockfile --store-dir .cache/pnpm-store`、`uv sync --frozen`；避免为了通过初始化随意改锁文件。

功能改动按范围执行：

```powershell
pnpm format
pnpm format:go
pnpm check
pnpm test
uv run --frozen tools/validate_schema.py --resource-dirs assets/resource --exclude-dirs assets/resource/gamedata assets/resource/image assets/resource/model --task-dirs assets/tasks
uv run --frozen build-and-install
uv run --frozen build-and-install --cpp-algo
```

纯文档改动检查文档格式、链接和差异即可。Go/C++ 修改必须重新编译相应 Agent。每阶段记录实际执行结果，区分已编译、自动检查通过、空跑通过、真实交付通过；不能把前一种当成后一种。

先上游步行和自动滑索基线，再固定逐跳空跑，再连滑和业务接入。按计划测试矩阵保留异常、双入口和持货恢复验证。已有上游检查失败要记录来源，不借机扩大修改范围。临时验证文件完成后清理，正式可复用测试保留。

## 6. GitHub 同步与接力

- `origin`：`https://github.com/MaaEnd/MaaEnd.git`，只读上游。
- `myfork`：`https://github.com/Hadrien-codeur/MaaEnd.git`，个人同步仓库。
- 开发分支：`codex/fixed-zipline-delivery`，两台电脑共同跟踪同一远端分支。
- 用户已授权本项目必要的 commit/push 用于接力，无需每次重新确认。向上游提 PR 或发布产品另按实际请求处理。
- 开始时先检查本地未提交改动，再 fetch 和比较。干净且可快进时使用 `pull --ff-only`；存在分叉时先保留两侧提交、理解冲突再处理，不强制覆盖。
- 更新上游与双电脑同步分开：前者需评估语义变化并复测，不能每次接力顺手合并最新上游。
- 收尾更新接力记录，明确阶段、已确认决策、测试、未完成项、下一步和本机环境；只暂存本次相关文件，使用 Conventional Commits 后推送，并比较本地 HEAD 与远端分支 SHA。
- 未完成代码允许作为标明 WIP 的保存点同步，但必须记录未通过项，不宣称已验收。推送失败必须明确说明本机有未同步工作。
- 账号凭据、原始设施快照、个人配置、日志、安装产物和缓存不进入仓库；路线配置与经过脱敏的必要测试证据按计划维护。
- 子模块自有改动需先在其可访问仓库保存并推送，再提交主仓库指针；不能仅推主仓库而使家里无法获取依赖。
- 接力记录持续保留并更新，不在接力后删除。新电脑需重建环境及程序；二进制不随 Git 同步。
