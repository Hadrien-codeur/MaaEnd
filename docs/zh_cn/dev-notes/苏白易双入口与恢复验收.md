两类任务均已加入“使用已配置的固定滑索路线”开关，位于“送货时优先使用滑索”开启后的子选项，默认关闭，仅支持 Win32-Front。实际配置读取自 `AutoDeliveryNavigateDepot.attach` / `AutoDeliveryNavigateDestination.attach`：

| 设置 | 实际导航 |
| --- | --- |
| `zip=false` | 普通步行，优先于固定开关 |
| `zip=true`，固定关闭 | 原 `WithZipline` 自动规划，不携带固定 ID |
| `zip=true`，`fixed_zipline=true`，目录有固定节点 | 新 `WithFixedZipline` 节点，使用完整固定架序与已确认连滑区间 |
| 开启固定，但终点未配置 | 原 `WithZipline` 自动规划 |
| 开启固定且全局 Never | Go 在业务移动前选择普通步行，日志记录 `global_zipline_never` |

严格独立测试入口仍由 C++ 拒绝全局 Never。固定配置损坏、设施缺失、匹配歧义或固定段运行失败仍停止；本轮只完成未配置终点和全局禁滑两类分流，没有增加“失败后重跑上游路线”。完整的设施预检降级与恢复矩阵仍待开发 / 验收，P4 未全部完成。

## 本轮修补

`FixedWulingSubaiyiDeliveryTest` 原来只指定 `SeizeDeliveryJobsMain`，没有任务选项，默认后处理关闭，不能保证进入完整送货。本轮让它复用正式抢单的奖励、来源和后处理选项，包含既有风险确认、滑索偏好和循环次数；不复制或改写业务 Pipeline。

使用“武陵城苏白易接单实测”时，选择武陵城来源、技术生产办公室（苏白易）目的地、全自动送货、既有风险确认，并启用“送货时优先使用滑索”和其下的“使用已配置的固定滑索路线”。入口名称本身不强制筛选苏白易，也不默认开启全自动送货。新 Go Agent 已编译安装，重新启动 Agent 并加载资源后生效；原用户配置只有滑索偏好时，默认恢复自动规划，需要显式开启新增固定选项。

原生规划测试改为从固定架序数据与地图变换核对每一跳的起终点，地面路径新增 ZONE / 数组点不会被误当成架子；必经动作反例明确插入中途 required NAVMESH。同时补充生成业务节点中的武陵取货方向与零次接力校验。
