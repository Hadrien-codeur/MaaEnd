## 每笔订单记录

每次实测至少记录以下字段，日志中能确认的内容优先于手工描述：

- 入口：`SeizeDeliveryJobs` 或 `DeliveryJobs`；新订单、已有委托或持货恢复。
- 区域、目的地文案、解析出的 `source_id` 和实际 `fixed_route_node`。
- 选项：风险确认、送货时优先使用滑索、使用已配置的固定滑索路线；控制器必须是 `Win32-Front`。
- 取货结果、架序 / E 接力结果、末架定位、离索地面段、最终交付提示。
- 任务结果：返回抢单循环、返回装箱仓储循环、成功停止或失败停止；失败时记录是否继续装箱。

## 必测分流

| 场景 | 预期行为 | 实机状态 |
| --- | --- | --- |
| 固定路线关闭 | 使用上游普通自动滑索 | 待测 |
| “送货时优先使用滑索”关闭 | 使用步行路线 | 待测 |
| 全局滑索 `Never` | 业务入口在移动前改走步行 | 待测 |
| 未配置固定终点 | 使用上游自动规划 | 离线已覆盖，业务待测 |
| 已有委托 / 非仓储位置恢复 | 按任务详情状态继续，不重复取货 | 待测 |
| 固定段失败或取消后重启 | 停止当前任务，不继续装箱；重启不继承旧状态 | 待测 |

固定路线选项当前仅对 `Win32-Front` 显示。设施缺失、架序歧义和固定段运行失败仍采用严格停止语义，不自动切换上游路线后伪报固定路线成功。

## 证据门槛

七个终点至少各有一笔正式入口成功记录后，才能把“正式业务接入”标为通过；两类入口、已有委托 / 持货恢复和失败停止仍需分别完成，不能由单笔正常订单代替。
